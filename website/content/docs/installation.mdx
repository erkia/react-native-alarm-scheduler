
<Callout type="warn" title="Not available in Expo Go">
This module ships native code. Use a development build or a prebuilt native app.
Expo is optional. Both bare React Native and Expo apps use the same React Native TurboModule.
React Native 0.79+ and the New Architecture are required.
</Callout>

## Bare React Native setup

Expo and Expo Modules are not required. The package autolinks through React Native.
Use React Native 0.79+ with the New Architecture enabled, then rebuild your app.

### Android

Add these permissions above `<application>` in your app's
`android/app/src/main/AndroidManifest.xml`:

```xml
<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM" />
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
<uses-permission android:name="com.android.alarm.permission.SET_ALARM" />
```

The library contributes its receivers, ring activity, foreground service, and other
ringing permissions through manifest merging. Request notification permission at runtime
on Android 13+ when needed; declaring it does not grant it.

### iOS

Run `cd ios && pod install`, then add these entries to the app's `Info.plist`:

```xml
<key>NSAlarmKitUsageDescription</key>
<string>Allow this app to schedule alarms.</string>
<key>NSSupportsLiveActivities</key>
<true/>
```

Add `node_modules/react-native-alarm-scheduler/assets/alarm-scheduler-silence.caf` to the
app target's **Build Phases → Copy Bundle Resources** in Xcode. It must be in the main app
bundle for `ios.silent: true`. Add any files referenced by `ios.soundName` to the same phase.
Runtime `soundUri` imports need no bundled sound entry.

Rebuild the native app. Actual iOS scheduling still requires the iOS 26 SDK and an iOS 26+
device; the module reports unavailable on older systems.

## Expo setup (optional config plugin)

Add the plugin to your app config before running `expo prebuild`:

```json title="app.json"
{
  "expo": {
    "plugins": [
      [
        "react-native-alarm-scheduler",
        {
          "alarmKitUsageDescription": "Allow this app to schedule alarms.",
          "addExactAlarmPermission": true,
          "addNotificationPermission": true,
          "iosAlarmSounds": ["./assets/audio/morning-alarm.caf"]
        }
      ]
    ]
  }
}
```

Then rebuild the native projects:

```sh
npx expo prebuild
npx expo run:android
npx expo run:ios
```

## Plugin options

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `alarmKitUsageDescription` | `string` | `Allow this app to schedule alarms that can alert you at the selected time.` | Adds `NSAlarmKitUsageDescription` for iOS AlarmKit authorization. |
| `addExactAlarmPermission` | `boolean` | `true` | Adds `android.permission.SCHEDULE_EXACT_ALARM`. |
| `addNotificationPermission` | `boolean` | `true` | Adds `android.permission.POST_NOTIFICATIONS`. |
| `addUseExactAlarmPermission` | `boolean` | `false` | Adds `android.permission.USE_EXACT_ALARM`, which is granted without prompting. Google Play only allows it for apps whose core function is an alarm clock or calendar. |
| `iosAlarmSounds` | `string[]` | `[]` | Adds a developer-owned sound catalog to the iOS app bundle. Runtime user-selected sounds use `soundUri` and need no config entry. |

The plugin also enables `NSSupportsLiveActivities` for iOS AlarmKit intents and adds
`com.android.alarm.permission.SET_ALARM` for Android system Clock alarm intents. It also bundles the
package's internal iOS silence asset automatically; `silent: true` needs no plugin option.

## What the package adds on its own

After completing the bare setup or applying the Expo plugin, the package's own Android manifest contributes the
permissions the ringing layer needs — `WAKE_LOCK`, `VIBRATE`, `RECEIVE_BOOT_COMPLETED`,
`USE_FULL_SCREEN_INTENT`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE`, `DISABLE_KEYGUARD`
and `TURN_SCREEN_ON` — plus the ringing service, the lock-screen ring activity, and the boot receiver.

<Callout title="Play Console justification">
The foreground service is declared as `specialUse` with the subtype `alarm`. Play Console asks for a
short justification for that type; "the service plays the alarm and keeps the ringing UI alive until
the user completes the wake-up flow" is the honest one.
</Callout>

## Requirements

- React Native 0.79+ with the New Architecture enabled (Expo SDK 53+ when using Expo).
- Android API 24+, or the higher minimum required by your React Native version.
- iOS 15.1+, or the higher minimum required by your React Native version.
- iOS 26 SDK **and** iOS 26 runtime for actual AlarmKit scheduling. Older iOS versions report
  `status: 'unavailable'`.
